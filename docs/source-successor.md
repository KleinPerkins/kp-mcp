# Source successor boundary

This source-only successor starts without the original repository's Git history. The original repository, tags, historical implementation evidence and private operational/discovery records remain private and preserved. They are not inherited release evidence.

Runtime source, synthetic tests, product/reference documentation and reviewed delivery preparation are retained. This preparation does not alter installed runtimes, operator profiles, credentials, host jobs, consumer pins or original repositories. Existing old commits/tags continue to belong to the retained original; do not recreate them by importing history.

Repository identity is new. The exact clean source was admitted under the owner release. WORK source enrollment requires fresh successor source review, candidate hosted CI, owner-visible controls and owner initial enrollment admission; PERSONAL remains disabled pending separate qualification. After admission, admitted-main CI and repository-scoped read-only App qualification must pass before separate operational writer activation. Account-bound ordinary PR creation, current review/CI/control admission and an actual App-owned native squash still require their own evidence.

Frozen registrar ADR files retain their original approval/provenance bytes and original repository identifiers as design provenance. The original active doc-warden registration and receipts are excluded. The successor is not enrolled in doc-warden by their presence; repository registration/adoption is a separate owner workflow.

## Private operational record omitted

`docs/dev/INDEX-GRADUATION.md` is excluded from this successor: it describes a private consumer inventory and migration, not a generic product contract. Its original bytes remain privately preserved. For any future index delivery, decide the index, authentication and consumers from the actual authorized scope; use `docs/dev/RELEASE.md` for local packaging guidance. No original consumer pin, credential, installation or publication is changed by this source preparation.

Examples and offline fixtures use synthetic identities, an `EXAMPLE_DB` database and Example Shop data. Snowflake bootstrap resolves a username only from explicit environment/profile or an existing registration; it no longer guesses one from Git email or an organization domain. The Google Drive upload default is the neutral `google-kit-uploads` folder. Existing installed runtimes are unaffected.

## Prepared App delivery controls

The successor enrollment retains repository-specific CI jobs, shard/skip rules and aggregate receipts. App qualification uses current controls only; retired controller blockers and bootstrap qualification are rejected. Before qualification and each App write, the actual scoped App credential must observe every contributing effective ruleset as active with `current_user_can_bypass: never`. A redacted bypass actor list does not prove this status.

Ordinary delivery rechecks the current review, CI run, source head, base and trusted policy. Existing or unknown native auto-merge requests stop admission for read-only reconciliation. A single existing App approval for the exact head may be reused; both reused and newly submitted approvals are reread before native delivery. App-only native squash or arming requires actor and state readback; ambiguous responses never trigger a blind retry. Native strict checks arbitrate later head/base races. The owner accepted the unavoidable race in which a concurrent foreign actor arms auto-merge after the last read; these checks do not claim atomic exclusion of that actor.

Q16 receipts are operational local trust, not cryptographic anti-forgery evidence. Initial source preparation did not itself qualify hosted CI, App installation/enrollment, source publication, successor name cutover or production runtime. Initial enrollment admission records must bind fresh source review, candidate CI and owner-control evidence. Admitted-main CI and read-only App qualification follow admission and precede operational writer activation; production runtime remains outside this source delivery.
