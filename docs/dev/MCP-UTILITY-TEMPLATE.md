# MCP Utility Kit Template

Step-by-step recipe to create a new `<domain>-kit` in this workspace. This is the **across-kit** authoring recipe. For adding one service inside an existing kit, see [SERVICE-PATTERN.md](SERVICE-PATTERN.md).

> **Fastest path — scaffold, don't hand-copy.** A runnable skeleton lives in
> [`template/`](../../template/) and a generator renders it:
>
> ```bash
> uv run python tools/new_kit.py --domain widget   # creates widget-kit/
> uv sync --all-packages                           # installs the new member
> uv run pytest widget-kit/                         # sample tests pass
> ```
>
> The workspace auto-discovers any `*-kit` member and the parametrized CI
> (`tools/ci_discover.py`) picks it up with no YAML edits. The sections below
> explain what the scaffold contains and why — read them when customizing.

---

## 1. Workspace position

This monorepo uses a `uv` workspace. Each kit is a separate Python package under the workspace root.

```
kp-mcp/                        ← workspace root (pyproject.toml, uv.lock)
  kp-mcp-bootstrap/            ← shared engine: detect, registrars, secrets, oauth, docgen
  kp-mcp-testkit/              ← shared test engine: fixtures, parity, faults, editorial lint, doc-runner
  google-kit/                  ← kit #1 (reference implementation)
  <domain>-kit/                ← your new kit (follows this template)
```

The workspace root `pyproject.toml` declares every member under `[tool.uv.workspace] members`:

```toml
[tool.uv.workspace]
members = ["kp-mcp-*", "*-kit"]
```

Any directory matching `*-kit` is automatically discovered as a workspace member.

## 2. Directory layout

```
<domain>-kit/
  pyproject.toml
  src/<domain_pkg>/
    __init__.py                 # __version__, triggers service auto-registration
    cli/
      __init__.py
      auth.py                   # auth login/logout/status subcommands
    mcp/
      __init__.py
      __main__.py               # stdio MCP entry point
    core/
      client.py                 # execute_api_call wrapper (uses kp-mcp-bootstrap)
      normalize.py              # OutputEnvelope, Meta
      redaction.py              # PII scrub before audit log
      retry.py                  # exponential back-off
      run_id.py                 # per-call UUID correlation
    registry.py                 # OpSpec class + register() + all_specs()
    schema_gen.py               # writes docs/schemas/<name>.json + _manifest.json
    docgen_gen.py               # writes docs/cards/<name>.md + docs/INDEX.md
    bootstrap.py                # wires CLI bootstrap subcommand → registrars
    services/
      __init__.py               # auto-discovers service sub-packages via pkgutil
      <svc>/
        __init__.py             # OpSpec registration (see SERVICE-PATTERN.md)
        models.py               # Pydantic input/output models
        core.py                 # typed core functions
  docs/
    QUICKSTART.md
    INDEX.md                    # generated by docgen_gen
    cards/                      # generated by docgen_gen
    schemas/                    # generated by schema_gen
  tests/
    test_<svc>.py               # mock-read + mutation-request parity tests
  fixtures/
    golden/
      <svc>/
        <op>_response.json
        <op>_expected.json
        <op>_expected_body.json
  rules/
    <domain>-kit-mcp-safety.mdc
```

## 4. Consuming kp-mcp-bootstrap

### 4a. OpSpecLike protocol (docgen contract)

`kp-mcp-bootstrap` exposes `kp_mcp_bootstrap.docgen.OpSpecLike` — the protocol your kit's `OpSpec` must satisfy. Your `registry.py` defines `OpSpec` and `register()` locally; `kp-mcp-bootstrap` provides the protocol so docgen works without a circular import.

```python
# <domain_pkg>/registry.py
from kp_mcp_bootstrap.docgen import OpSpecLike
from pydantic import BaseModel
from typing import Any, Callable

class OpSpec:
    name: str
    fn: Callable[..., Any]
    input_model: type[BaseModel]
    output_model: type[BaseModel]
    posture: str           # 'read' | 'write' | 'destructive' | 'admin'
    scopes: list[str]
    perf: dict[str, Any]
    batching: dict[str, Any]
    formatting: dict[str, Any]
    examples: list[Any]

_REGISTRY: list[OpSpec] = []

def register(spec: OpSpec) -> None:
    _REGISTRY.append(spec)

def all_specs() -> list[OpSpec]:
    return list(_REGISTRY)
```

### 4b. Docgen engine

```python
# <domain_pkg>/docgen_gen.py
from kp_mcp_bootstrap.docgen import Docgen
from <domain_pkg>.registry import all_specs
import <domain_pkg>  # noqa: triggers auto-registration

docgen = Docgen()
for spec in sorted(all_specs(), key=lambda s: s.name):
    md = docgen.emit_markdown(spec)
    # write to docs/cards/<spec.name>.md
```

`Docgen.emit_markdown()`, `emit_mcp_schema()`, and `emit_cli_help()` are fully generic — they consume the `OpSpecLike` protocol and need no kit-specific customization.

### 4c. Auth / Keychain / Registrars

`kp_mcp_bootstrap.secrets.SecretStore` — reads/writes macOS Keychain; service name = kit name.

`kp_mcp_bootstrap.oauth.run_pkce_flow()` — performs the PKCE loopback OAuth flow.

`kp_mcp_bootstrap.detect.detect_env()` — returns the active agent platform (`cursor` | `codex` | `claude` | `unknown`).

Registrars (`CursorRegistrar`, `CodexRegistrar`, `ClaudeRegistrar`) reconcile
owned fields through explicit preview, prepare and apply stages. Subclass
`SERVER_NAME` as in the scaffold and supply the kit's stable source identity in
`RegistrationContext`. Never infer ownership from an equal launch command.

```python
preview = registrar.preview(config_path, definition, context=context)
prepared = registrar.prepare(preview)
# Approval comes from the existing owner workflow for these exact prepared bytes.
result = registrar.apply(prepared, approval)
```

Preview is read-only; prepare is a separately authorized private-state write.
Apply requires the exact prepared payload and operation-bound approval. Full
batches preflight before the first target write and report partial outcomes.
`current_entry` now returns a bounded Inspection and requires context; consumers
must use owned-projection matching rather than full native-entry comparisons.
Only disposable fixtures qualify for writes in this source version. Live
registration returns `concurrency_unqualified` until native exclusion is
separately qualified; no CLI flag can waive that boundary.

## 5. Consuming kp-mcp-testkit

### 5a. Mock service fakes

`kp_mcp_testkit.mock_google.MockGoogleService` is Google-specific (it belongs to the reference kit). For a new domain, ship a lightweight backend fake that records calls and returns canned responses — the scaffold's [`template/tests/conftest.py.tmpl`](../../template/tests/conftest.py.tmpl) `FakeBackend` is exactly this pattern:

```python
class MockDomainService:
    def __init__(self, responses: dict[tuple[str, str], Any]) -> None:
        self._responses = responses
        self._calls: list[tuple[str, str, Any]] = []

    def resource(self) -> "MockResource":
        return MockResource(self)

    def last_request_body(self) -> Any:
        return self._calls[-1][2] if self._calls else None
```

Place the mock in `<domain>-kit/tests/conftest.py` or contribute it to `kp-mcp-testkit` when it becomes stable.

### 5b. Parity harness

```python
from kp_mcp_testkit.parity import compare

parity = compare("normalized-json", expected, result.data.model_dump())
assert parity.match, parity.diff
```

Comparators: `normalized-json` (field-exact), `semantic` (structural), `mutation-request` (request body).

### 5c. Golden fixtures

```
<domain>-kit/fixtures/golden/<svc>/
  <op>_response.json        # raw API response
  <op>_expected.json        # expected result.data.model_dump()
  <op>_expected_body.json   # expected request body (write ops)
```

Load with `kp_mcp_testkit.fixtures.load_fixture(path)`.

### 5d. Fault injection

```python
from kp_mcp_testkit.faults import inject_transient, inject_quota
```

### 5e. Editorial lint

The `kp_mcp_testkit.editorial` module enforces R29 discipline across all `.py` and `.md` files. Add your kit's paths to the CI editorial lint step (see §7).

### 5f. Doc-runner gate

```python
from kp_mcp_testkit.doc_runner import run_doc_suite
```

Runs the doc task suite JSON against real CLI output. Gate: all tasks pass before a release is tagged. Configure in `docs/dev/DOC-TASK-SUITE.md` + `docs/dev/doc_task_suite.json`.

## 6. Single-core / dual-surface pattern

One core function. Two surfaces (CLI + MCP). Both delegate to the same registry.

```
registry.py (OpSpec entries)
    └── services/<svc>/core.py       (typed core fn)
            ↑
   cli/__init__.py  ← argparse surface (reads stdin/env, calls core, prints JSON)
   mcp/__init__.py  ← MCP stdio surface (reads MCP protocol, calls core, emits MCP response)
```

Rules:
- Core functions have no `argparse`, no `print`, no `sys.exit`. They accept a Pydantic input model and return `OutputEnvelope[XxxData]`.
- The `service` parameter is the only test-injection seam. Default `None` → real auth via Keychain.
- `execute_api_call` (in `core/client.py`) wraps retry / classify / observe / audit automatically. Never call the API directly.

## 7. OpSpec registry

Every capability = one `OpSpec` entry. See [SERVICE-PATTERN.md § OpSpec registration](SERVICE-PATTERN.md#opspec-registration) for the full field reference. The minimal fields:

```python
register(OpSpec(
    name="<svc>.<op>",
    fn=svc_op,
    input_model=SvcOpInput,
    output_model=SvcOpOutput,
    posture="read",           # 'read' | 'write' | 'destructive' | 'admin'
    scopes=["https://..."],
    perf={"api": "...", "method": "...", "quota": "..."},
    batching={"supported": False},
    formatting={"default": "normalized-json"},
    examples=[{"description": "...", "input": {}, "cli": "<domain>-kit <svc> <op>"}],
))
```

## 8. Docgen cards

After adding all ops, generate cards and the index:

```bash
uv run python -m <domain_pkg>.docgen_gen
```

Writes:
- `<domain>-kit/docs/cards/<name>.md` — one card per op
- `<domain>-kit/docs/INDEX.md` — intent → card resolver

## 10. Empirical doc-loop gate

Before tagging a release:

1. Run the doc task suite against a live account: `uv run python -m kp_mcp_testkit.doc_runner docs/dev/doc_task_suite.json`.
2. Fix any failing tasks (real auth required; use a sandbox account).
3. Record pass/fail in `docs/DOC-LOOP-REPORT.md`.

The gate exists so docgen cards stay accurate under real API behavior, not just mock fixtures.

## 11. Safety rule

Create `<domain>-kit/rules/<domain>-kit-mcp-safety.mdc`:

```yaml
---
description: >
  Safety guardrails for agents invoking <domain>-kit via MCP. Load when using
  any <domain>-kit MCP tool or reviewing code that calls these tools.
globs:
alwaysApply: false
---

# <Domain>-kit MCP Safety Rule

## Tool Postures and Confirmation Requirements

| Posture | Confirmation required | Retry on failure |
|---------|----------------------|------------------|
| `read` | Never | Yes (transient/quota) |
| `write` | Before first mutation in session | Yes (transient/quota) |
| `admin` | Always, before each call | No |
| `destructive` | Always, before each call | Never |

## Scope and Secret Hygiene

Never pass credentials as tool arguments. All auth is handled server-side via the macOS Keychain.

## Error Taxonomy

| Error class | Agent action |
|-------------|-------------|
| `Transient` | Handled automatically (max 4 attempts); escalate if all fail |
| `QuotaRateLimit` | Wait `retry_after`; retry once; escalate |
| `Auth` | Stop; inform operator to run `<domain>-kit auth login` |
| `Permission` | Stop; do NOT retry |
| `NotFound` | Surface error; do NOT retry |
| `Validation` | Fix input; retry once |
| `Unknown` | Escalate immediately |
```

## 12. Registrars — agent platform wiring

The `bootstrap` CLI subcommand reports a bounded refusal when the owner context,
prepared operation or approval is unavailable. It never manufactures them.
Use the scaffold's explicit Python inputs from the owner workflow; native live
writer qualification remains unavailable in bootstrap 0.3.0. No service or auth
operation follows registration implicitly. Tests use disposable isolated roots,
never the operator's Cursor, Codex or Claude config.

## 14. Catalog registration

[docs/CATALOG.md](../CATALOG.md) is **generated** — do not hand-edit it. The
generator discovers every `*-kit` member and derives op/service counts from the
registry, so registering your kit is one command:

```bash
uv run python tools/catalog_gen.py
```

Commit the regenerated `CATALOG.md` (and `ECOSYSTEM.md` counts block). The CI
determinism gate double-runs the generator and fails on any drift, so the
dashboard can never disagree with the shipped ops.
